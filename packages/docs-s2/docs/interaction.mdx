# ChartInspect and ChartPopover

<StageBadge />

`ChartInspect` shows a tooltip with details about the data point under the pointer. `ChartPopover`
opens a popover when a data point is clicked, for content the user can interact with, like links
or buttons. Neither renders anything itself: add them as children of a mark, and pass a function
as children that returns the content for a data point.

<InteractionPlayground />

## Data

Most examples on this page use a line chart of `interactionVisitorsData` or a stacked bar chart of
`interactionDownloadsData`. Each row has an `id` field, used in [Highlighting](#highlighting).

<DataCode name="interactionVisitorsData" />

<DataCode name="interactionDownloadsData" />

```tsx
<Chart data={interactionVisitorsData}>
  <Line dimension="month" metric="visitors" color="device" scaleType="point">
    <ChartInspect>{(datum) => <div>{datum.visitors} visitors</div>}</ChartInspect>
    <ChartPopover>
      {(datum, close) => (
        <Button variant="secondary" size="S" onPress={close}>
          Close
        </Button>
      )}
    </ChartPopover>
  </Line>
</Chart>
```

## Content

`ChartInspect` children are a function that takes the hovered data point, `datum`, and returns
React content. `ChartPopover` children take the clicked `datum` and a `close` function that closes
the popover.

The content can be any React content. The popovers on this page use Spectrum 2 components from
`@react-spectrum/s2`, like `Heading`, `Content`, `Text`, and `Button`, except the [Size](#size)
example, which uses custom HTML.

`datum` is the row from `data`, plus fields the chart adds:

- `rscComponentName`: the name of the mark that was hovered or clicked, like `line0` or `bar0`.
  Use it to tell marks apart when a chart has more than one.
- `rscMarkId` and `rscSeriesId`: the row's ID and series.
- `rscGroupData`: the rows in the highlighted group, when [`highlightBy`](#highlightby) isn't
  `'item'` or the inspect is over a [dimension area](#targets).

Other internal fields, like stack offsets on bars, may also appear. Use **raw datum** below to see
everything a mark passes.

<InteractionContentPlayground />

### Default content

Only [Donut](./donut.mdx#chartinspect-and-chartpopover) has default content: without children,
its inspect and popover show the segment's color, name, share of the total, and value. On other
marks, an inspect or popover without children shows nothing, although the mark still responds to
the pointer.

On `Line`, adding `ChartInspect` turns off the line's built-in hover label, which shows the hovered
value on the axis.

## ChartInspect

### Placement

The inspect follows the cursor by default. Set `tooltipAnchor="mark"` on `Chart` to anchor it to the
hovered mark instead, and `tooltipPlacement` to place it on the `top` (default), `bottom`, `left`,
or `right` of the mark. `tooltipPlacement` only applies when the inspect is anchored to the mark.

<InteractionAnchorPlayground />

### highlightBy

While the inspect is visible, the hovered point stays at full opacity and other points fade.
`highlightBy` sets what stays highlighted:

- `'item'` (default): the hovered point.
- `'series'`: every point in the hovered point's series (the `color` field).
- `'dimension'`: every point at the hovered dimension value, like a month or a browser.
- A list of field names: every point that matches the hovered point on all of those fields, like
  `['browser', 'os']`.

With any value other than `'item'`, `datum.rscGroupData` holds the rows in the highlighted group,
so the inspect can summarize them. The example below counts and totals the group.

<InteractionHighlightByPlayground />

### targets

On stacked or dodged bars, `targets` sets what shows the inspect. `'item'` (default) is a single
bar. `'dimensionArea'` is the whole column for a dimension value, including the padding around its
bars; hovering the empty space in a column shows the inspect for that column, with its bars in
`datum.rscGroupData`. Pass both to inspect bars and columns.

<InteractionTargetsPlayground />

`targets` only applies to `Bar`. Hovering a bar shows its own inspect even when `targets` leaves
out `'item'`.

### excludeDataKeys

`excludeDataKeys` lists fields that turn off the inspect for a row: rows with a truthy value in any
of these fields don't show an inspect or fade the rest of the chart. Below, Linux downloads are
estimates, flagged with `isEstimate`:

## ChartPopover

### Opening and closing

Clicking a data point opens the popover above it. It closes when the user clicks outside it,
presses `Escape`, or your content calls `close`. While a popover is open, the clicked point stays
highlighted and `ChartInspect` doesn't show.

Set `rightClick` to open the popover on right-click instead of click, for example to show a context
menu. A mark can have one click popover and one right-click popover.

:::note
The popover always opens above the clicked point and moves only to stay on screen. There's no
`placement` prop. `UNSAFE_highlightBy` sets what stays highlighted while the popover is open, like
`highlightBy` on `ChartInspect`; it's incomplete and may change.
:::

### Size

Without `width`, the popover fits its content. Set `width` to a number of pixels or `'auto'`, and
limit it with `minWidth` (default `0`) and `maxWidth`. `height`, `minHeight`, and `maxHeight` work
the same way. `contentMargin` (default `12`) is the space between the popover's edge and its
content. `containerPadding` (default `12`) is the closest the popover gets to the edge of the
window.

This example's popover content is custom HTML with inline styles rather than Spectrum 2 components,
to show that the popover takes any React content.

<InteractionPopoverSizePlayground />

### Callbacks

`onOpenChange` is called with `true` when the popover opens and `false` when it closes. `onClick`
on the mark is called with the clicked `datum`; on `Line` and `Bar` it fires along with the
popover.

```tsx
<Chart data={interactionDownloadsData}>
  <Bar
    dimension="browser"
    metric="downloads"
    color="os"
    onClick={(datum) => setSelected(datum.id)}
  >
    <ChartPopover onOpenChange={(isOpen) => setIsPopoverOpen(isOpen)}>
      {(datum, close) => <DownloadsDetails datum={datum} onDone={close} />}
    </ChartPopover>
  </Bar>
</Chart>
```

### Legend popovers

`Legend` can have a `ChartPopover` too. Clicking an entry opens it, with the entry's series name in
`datum.value` and `datum.rscSeriesId`. A legend with a click popover can't hide series on click.

<InteractionLegendPlayground />

## Using both together

A mark can have a `ChartInspect` and a `ChartPopover`. The inspect shows on hover, and clicking
opens the popover and hides the inspect until the popover closes. Use the inspect for a quick read
of the value and the popover for details and actions.

On `Line`, a click `ChartPopover` can't be combined with a
[`ChartActionBar`](./chart-action-bar.mdx): only the action bar renders. Use `rightClick` on the
popover to have both.

## Supported marks

| Mark                                       | ChartInspect | ChartPopover |
| ------------------------------------------ | ------------ | ------------ |
| [Line](./line.mdx)                         | Yes          | Yes          |
| [Bar](./bar.mdx)                           | Yes          | Yes          |
| [Donut](./donut.mdx#chartinspect-and-chartpopover) | Yes, with default content | Yes, with default content |
| [Legend](./legend.mdx)                     | No           | Yes          |
| Area (lab)                                 | Yes          | Yes          |
| Scatter (lab)                              | Yes          | Yes          |
| Bullet (lab)                               | Yes          | No           |
| Trendline (lab)                            | Yes          | No           |

Lab components are imported from `@spectrum-charts/react-spectrum-charts-s2/lab`. Some marks change
how hovering works, like `interactionMode` on `Line`; see each chart's page.

## Highlighting

`ChartInspect` highlights what's under the pointer. To highlight from outside the chart, for
example from a table row, use these `Chart` props:

- `highlightedSeries`: a series value, like `'Mac'`. Other series fade.
- `highlightedItem`: one row ID or a list of them. Other rows fade.
- `idKey`: the field that uniquely identifies each row, used by `highlightedItem`. Set it to a field
  in your data, like `id`.

Hovering the chart overrides these while the pointer is over a mark. The controlled highlight
returns when the pointer leaves.

In the example below, the table and the chart share state. Hovering a table row or selecting rows
sets `highlightedItem` to that browser's bars. Hovering a bar calls `onMouseOver`, which bolds its
value in the table, and clicking a bar calls `onClick`, which selects its browser's row. While a
bar is hovered, the chart highlights that bar instead of `highlightedItem`.

<InteractionHighlightPlayground />

The code panel shows only the chart. The table is a Spectrum 2 `TableView` that shares state with
it:

```tsx
const [selectedBrowsers, setSelectedBrowsers] = useState(new Set(['Safari']));
const [hoveredBrowser, setHoveredBrowser] = useState();
const browsers = hoveredBrowser ? [hoveredBrowser] : [...selectedBrowsers];
const getIds = (browser) => ['Windows', 'Mac', 'Linux'].map((os) => `${browser}-${os}`);

<Chart
  data={interactionDownloadsData}
  idKey="id"
  highlightedItem={browsers.length ? browsers.flatMap(getIds) : undefined}
>
  …
</Chart>

<TableView
  aria-label="Downloads by browser"
  selectionMode="multiple"
  selectedKeys={selectedBrowsers}
  onSelectionChange={setSelectedBrowsers}
>
  <TableHeader>…</TableHeader>
  <TableBody>
    <Row
      id="Chrome"
      onMouseEnter={() => setHoveredBrowser('Chrome')}
      onMouseLeave={() => setHoveredBrowser(undefined)}
    >
      …
    </Row>
    …
  </TableBody>
</TableView>
```

:::note
On `Line`, `highlightedItem` with a custom `idKey` marks the highlighted point but doesn't fade the
other series.
:::
