# Chart

<StageBadge />

`Chart` is the container for every chart. It takes the data, size, colors, and locale, and holds
state shared by its children, like hidden and highlighted series. Marks (`Line`, `Bar`, `Donut`,
and others), `Axis`, `Legend`, and `Title` go inside it as children.

<ChartPlayground />

`Chart` needs at least one child, or a Vega spec in `UNSAFE_vegaSpec` (see [Advanced](#advanced)).
It throws if it has neither, or both.

## Data

`data` is an array of objects, one per data point. Each mark reads the fields you name in its
props. Every example on this page uses `chartTrafficData`:

<DataCode name="chartTrafficData" />

```tsx
<Chart data={chartTrafficData}>
  <Axis position="bottom" labelFormat="time" baseline ticks />
  <Axis position="left" grid />
  <Line color="series" />
</Chart>
```

Here `Line` draws a line for each `series`, plotting `value` against `datetime`. `Line` reads
`datetime` and `value` by default, so the code only needs to name the `color` field.

### idKey

`idKey` names the field that uniquely identifies each row. The chart adds its own row ID by
default, so you only need `idKey` to refer to rows from outside the chart, as with
`highlightedItem`:

<ChartIdKeyPlayground />

### Empty and loading

When `data` is empty, the chart shows an icon and `emptyStateText` (default `No data found`) in
place of the chart. `loading` shows a progress circle instead. Both fill the chart's height.

<ChartStatesPlayground />

`EmptyState` and `LoadingState` are the components the chart renders for these states. They're
exported so you can show the same placeholders outside a chart, for example while fetching data
before you render one.

```tsx
<EmptyState height={300} text="No visits yet" />
<LoadingState height={300} />
```

## Size

`width` is a number of pixels, `auto` (the default) to fill the parent's width, or a percentage of
the parent's width, like `'75%'`. `height` is a number of pixels (default `300`) or a percentage of
the parent's height. The chart resizes when its parent does.

`minWidth` and `maxWidth` clamp an `auto` or percentage width, and `minHeight` and `maxHeight`
clamp a percentage height. They don't affect pixel values. In the example below the chart sits in
a 512 × 360 `div`.

<ChartSizePlayground />

:::note
A percentage `height` only works if the parent has an explicit height. Otherwise the chart has no
height to measure against.
:::

The size is the whole chart, including axes, legend, and title; the plot area gets what's left.
Some marks also adapt to the chart's width: S below 400 px, M from 400 px, and L from 800 px. For
example, line strokes are 1.5, 2, and 2.5 px wide at S, M, and L.

### Padding

`padding` adds space between the chart's edge and its contents, as one number or per side, like
`{ top: 8, left: 16 }`. The default is `0`. The padding is inside `width` and `height`.

<ChartPaddingPlayground />

## Color and theme

### colorScheme and backgroundColor

`colorScheme` (`light` or `dark`, default `light`) picks the light or dark value of every
Spectrum color token in the chart, including the mark colors, axes, and text. Set it to match your
app's theme. `backgroundColor` fills the chart and is a Spectrum color token, like `gray-25`, or a
CSS color. The default is `transparent`.

<ChartThemePlayground />

### colors

`colors` sets the palette for any mark's `color` field. It takes a named palette, or a list of
Spectrum color tokens or CSS colors. The default palette is `s2Categorical20`; `s2Categorical6`,
`s2Categorical12`, and `s2Categorical16` are its first 6, 12, and 16 colors. Colors are assigned
to series in the order they appear in `data`, and repeat if there are more series than colors.

<ChartColorsPlayground />

`colors` also takes a 2D list, like `[['blue-1000', 'blue-700'], ['red-1000', 'red-700']]`: a
group of colors per series, for marks that encode color with two fields.

### Other scales

Marks can also use a field for line type or opacity. The chart's `lineTypes` and `opacities` set
the values for those encodings, the same way `colors` does for color. In the example below, `Line`
sets `lineType` and `opacity` to `series`, so each series gets the next line type and opacity in
the lists.

<ChartScalesPlayground />

`lineTypes` defaults to `['solid', 'dashed', 'dotted', 'dotDash', 'longDash', 'twoDash']` and
`opacities` to `[1]`. `lineWidths`, `symbolShapes`, and `symbolSizes` work the same way for marks
that encode those, like `Scatter`'s `lineWidth` and `size`, and for legend symbols.

### config

`config` is merged into the chart's [Vega config](https://vega.github.io/vega/docs/config/), so
you can override styles the component props don't cover. Prefer props where they exist; config
keys can change without notice.

## Locale

`locale` sets how numbers and dates are formatted in axes, labels, and default tooltip content.
Pass a locale code, like `'de-DE'`, or separate number and time locales, like
`{ number: 'de-DE', time: 'en-US' }`. You can also pass a Vega locale object. The default is
`en-US`.

<ChartLocalePlayground />

The axis above uses `numberFormat="standardNumber"` so every tick shows the locale's grouping
separator.

## Title and accessibility

`title` adds a title above the chart and is the default file name for `download()`. For more options, use a `Title`
child instead. See [Title](./title.mdx).

`description` sets the chart's accessible label (`aria-label`). Describe what the chart shows.

<ChartTitlePlayground />

## Hiding and highlighting

`hiddenSeries` and `highlightedSeries` hide or highlight series from outside the chart, for example
to sync the chart with a table. They're controlled: the chart shows what you pass and doesn't
change them itself. `highlightedItem` highlights rows by ID (see [idKey](#idkey)).

<ChartHighlightPlayground />

See [Highlighting](./interaction.mdx#highlighting) for how each mark shows highlighting.

## Tooltips

`tooltipAnchor` and `tooltipPlacement` set where `ChartInspect` content appears. By default it
follows the cursor. With `tooltipAnchor="mark"` it attaches to the hovered mark, on the side given
by `tooltipPlacement` (default `top`).

<ChartTooltipPlayground />

See [ChartInspect and ChartPopover](./interaction.mdx) for the content and behavior of tooltips
and popovers.

## Animation

`animationTypes` lists the animations to play. The default, `['hover', 'drawIn']`, eases marks in
and out of their faded state when the chart is hovered or highlighted, and animates marks in when
the chart first renders. Set `animationTypes={['hover']}` to turn off draw-in only.
`animations={false}` turns off every animation.

<ChartAnimationPlayground />

If the user prefers reduced motion, draw-in is skipped; hover animation still plays.

:::note
Line draws in on `time`, `linear`, and `point` scales only.
:::

## Exporting images

Pass a `ref` to get a handle with these methods. Each returns a promise, and rejects if there's no
chart to export, for example while loading or when there's no data.

- `download(fileName?)`: downloads a PNG. The file is named `fileName`, or the `title` if you
  don't pass one, or `chart_export`, followed by `.png`.
- `copy()`: copies a PNG to the clipboard.
- `getBase64Png()`: resolves to the PNG as a base64 data URL.
- `getSvg()`: resolves to the chart as an SVG string.

<ChartHandleExample />

## Advanced

- `renderer`: `svg` (default) or `canvas`. Canvas is faster for large datasets.
- `debug`: logs the generated Vega spec and inspect data to the console.
- `onVegaViewReady(view)`: called with the [Vega view](https://vega.github.io/vega/docs/api/view/)
  whenever it's created or recreated, for example after data changes.
- `UNSAFE_vegaSpec`: renders a Vega spec you write instead of building one from children. `data`
  can then also be a list of Vega datasets. You lose the Spectrum defaults the components apply.
- `dataTestId`: sets `data-testid` on the chart's container.
